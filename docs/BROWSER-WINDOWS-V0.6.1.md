# V0.6.1 Windows 浏览器运行说明

此工作副本基于 RonaldDeng/Rhine-Music-Demo 官方 `v0.6.1` 标签，提交 `e8723aa9b76836d296446ed973161484a40f8c3d`。沿用官方 TypeScript、Three.js、CSS、模型、字体和演示资源；保留作者、上游来源及许可。这是本地浏览器适配，不是新的官方发行版。

## 启动

安装 Node.js 22.12 或更新版本后，双击根目录的 `启动音乐播放器.cmd`，也可运行 `npm start`。启动器首次安装锁定依赖并构建，后续复用有效构建及同工程的运行服务；默认从 5175 开始选择可用端口，服务仅监听 `127.0.0.1`。

浏览器打开启动器打印的地址。尚无音乐时，可选择“先查看演示封面”，或在地址后加 `?demo=1`。演示封面不附带可播放歌曲。自己的曲库通过“设置 → 音乐库设置 → 文件夹与扫描”添加，使用 Windows 绝对路径，例如 `D:\Music`。原版档案入口为 `?original=1`。

启动后可以关闭终端，后台服务继续运行。需要停止时，可在任务管理器中按启动时记录的 PID 结束该工程的 Node.js 服务，避免结束其他工程。重启电脑后再次双击即可。

## 音频

Windows 使用浏览器音频输出，保留三档歌曲衔接、队列、音量及歌词。CoreAudio 是 macOS 专属输出，Windows 不提供此设备后端。

FFmpeg 与 ffprobe 用于多格式解码、DSD 转 PCM 和无缝播放。本副本依次检查项目内 `.tools/ffmpeg/bin/`、常见 macOS 路径和系统 PATH；Windows 自动识别 `.exe`。也可通过 `FFMPEG_PATH`、`FFPROBE_PATH` 指定可执行文件的绝对路径。个人曲库及音频缓存不提交到版本库。

当前机器的本地工具放在 `.tools/ffmpeg/bin/`，不属于源码分发。复制源码到其他电脑时需另行安装 FFmpeg 和 ffprobe，或自行放入这个目录。缺少解码器时仍可尝试浏览器原生支持的格式，设置中显示实际能力。

前端生产源码、材质、动画、歌词、主题和布局保持官方 V0.6.1 基准；适配集中于启动命令、npm 调用、后台窗口隐藏、Windows 可执行文件发现及平台测试。

- `npm ci`、TypeScript 与生产构建、完整 `npm run check:v061` 通过。离线资源标识为 `ab88bef581ac7f40`，与官方 V0.6.1 发布验证记录一致。`src/`、`public/`、`index.html` 和锁文件与官方标签没有差异。
- 启动器冷启动与第二次复用通过；中文、空格和特殊字符路径检查通过。本机 FFmpeg 9.0.2 与 ffprobe 已识别，后台服务仅绑定本机地址；曲库初始为空。
- 三张专辑、六首合成静音 WAV 和原创本地 LRC 的实际浏览器验收通过：晨雾／月影、搜索定位不播放、专辑详情、播放、歌词高亮、点行跳转、空格暂停／恢复、手动阅读／恢复跟随、歌词字体／34px 字号／顶部锚点和歌曲衔接设置保存、设置切页、总览、390×844 竖屏专辑及歌词。控制台错误、脚本异常、失败 HTTP 响应、外部请求均为零。
